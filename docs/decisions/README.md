# 架构决策记录

本目录记录会长期影响模块边界、领域模型、接口兼容性、安全或运行方式的决策。

## 何时新增 ADR

- 新增、拆分或合并 Maven 模块。
- 改变 `startup → biz → api` 依赖方向。
- 改变跨服务领域归属或 API 兼容策略。
- 引入新的数据库、消息系统、安全机制或部署模式。
- 一个方案存在多个合理选择，需要保留取舍理由。

普通缺陷修复、局部重构和临时实验通常不需要 ADR。

## 命名

```text
0001-short-decision-title.md
0002-next-decision.md
```

## 模板

```markdown
# 标题

## 状态

建议 / 已接受 / 已废弃 / 已替代

## 背景

需要解决的问题、约束和上下文。

## 决策

采用的方案及明确边界。

## 后果

收益、代价、风险和后续工作。
```

已有跨项目专题设计保留在 `docs/design`；当专题中的决定稳定并具有长期约束时，可以再提炼为 ADR。
